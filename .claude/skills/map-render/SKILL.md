# map-render — 부동산 멀티레이어 지도 렌더러

레이어 GeoJSON들을 하나의 인터랙티브 지도(`estate_map.html`)로 통합한다. 기존 `auction_crawling/map_with_infra.py`가 VWorld+카카오 베이스맵·클러스터·WMS 오버레이 구조를 이미 갖고 있으므로 그것을 뼈대로 삼는다.

## 워크플로우

### 1. 레이어 로드
`_workspace/layer_*.geojson`과 `zone_wms_config.json`(선택)을 읽는다. 각 파일은 `references/geojson-schema.md` 규격이라고 가정한다. 규격 위반이면 렌더하지 말고 qa-validator에 반려한다. **빈 FeatureCollection은 정상** — 해당 레이어를 "데이터 없음"으로 표시하고 계속 진행한다.

### 2. 레이어별 렌더 방식
| 레이어 | 렌더 | UI |
|--------|------|----|
| auction (Point) | 클러스터 마커, 용도별 색 | 레이어 토글 + 유찰 필터 |
| infra (Point) | 카테고리별 마커/클러스터 | 레이어 토글 + 카테고리 토글 |
| zone_* (Polygon/WMS) | 낮은 투명도 채움 + 외곽선, 또는 WMS 타일 | 레이어 토글 |

### 3. 시각 위계 (핵심)
- **면은 배경, 점은 전경**: 구역 폴리곤은 낮은 투명도로 깔고, 경매·POI 마커가 그 위에 오도록 렌더 순서/z-index를 잡는다. 구역이 마커를 덮으면 안 된다.
- 세 구역은 서로 다른 색 계열(정비=주황, 공공주택=청록, 산업단지=보라)로 겹쳐도 판독되게.

### 4. 토글 UI
왼쪽 상단 레이어 패널에 5개 최상위 토글 + infra 하위 카테고리 토글. 각 레이어는 **독립적으로** on/off — 한 레이어를 꺼도 나머지 정상. 초기 상태는 경매 on, 나머지 off 권장(첫 화면 과밀 방지).

### 5. 키·프록시
- 카카오 JS 키: 브라우저 `localStorage`에 저장(재입력 불필요) — `map_with_infra.py` 방식 계승.
- VWorld/공공데이터 WMS: `vworld-map` 스킬의 프록시 서버로 CORS 우회. HTML에 키 하드코딩 금지.

산출: `estate_map.html`(사용자 지정 경로).

## 왜 이렇게 하는가
- **스키마만 신뢰**: 렌더러가 레이어별 특수 처리를 하드코딩하면 레이어 추가마다 렌더러를 고쳐야 한다. 표준 스키마(`category`·`color`)에만 의존하면 새 레이어도 설정만으로 붙는다.
- **빈 레이어 허용**: 수집 실패가 전체 지도를 깨면 안 된다. 부분 데이터로도 지도는 떠야 한다.

## 산출 검증
- 5개 레이어 토글이 모두 동작하고, 각 토글이 정확한 레이어를 켜고 끄는가.
- 구역 폴리곤이 마커를 가리지 않는가(시각 위계).
- 빈 레이어가 있어도 지도가 정상 렌더되는가.
