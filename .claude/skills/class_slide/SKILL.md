# class_slide — 강의 슬라이드 웹앱

강의/발표 내용을 **넘기는 슬라이드 웹앱**(단일 HTML 아티팩트)으로 만든다. 정적 md 교안이 아니라, 한 화면에 한 개념씩 띄우고 방향키·버튼·스와이프로 넘기는 프레젠테이션이다.

## 언제 이 스킬인가
- "슬라이드/프레젠테이션/발표자료로 보여줘/만들어줘" → 이 스킬
- "강의 교안/문서로 정리해줘"(읽는 문서) → 이 스킬 아님(md 문서로)
- 이미 만든 슬라이드 "장 추가/순서 변경/색 바꿔줘" → 이 스킬(재발행)

## 워크플로우

### 1. 소스 확보
슬라이드로 만들 내용을 먼저 확보한다. 기존 교안·문서·대화 내용이 있으면 그걸 슬라이드 단위로 쪼갠다. 없으면 사용자에게 주제·핵심 메시지·대상 청중을 확인한다.

**한 슬라이드 = 한 개념.** 문장을 욱여넣지 말고, 헤드라인 + 3~5개 요점 + 시각 요소 하나로 압축한다.

### 2. 템플릿에서 시작 (바퀴 재발명 금지)
`assets/template.html`을 복사해 시작한다. 이 템플릿은 검증된 뼈대다:
- 디자인 토큰(라이트/다크), 반응형 타이포
- 네비게이션 JS(방향키·PageUp/Down·Space·Home/End·F 전체화면·터치 스와이프·테마 토글·진행바·슬라이드 카운터)
- 슬라이드 타입 예시 7종

JS·CSS 뼈대는 손대지 말고, `:root`의 `--accent`/`--accent2`만 주제 색으로 바꾸고 `<section class="slide">`들을 콘텐츠로 채운다.

### 3. 색 정하기 (주제에서 유도)
AI 기본값(크림+세리프, 보라 그라디언트)을 피하고 **주제 세계관에서 색을 끌어온다**. 이미 만든 산출물이 있으면 그 색을 계승한다(예: 이 프로젝트는 지도 마커 민트 `#0ca678` + 정비구역 바이올렛 `#7c3aed`).
- `--accent`: 주 강조(진행바·kicker·주요 스탯)
- `--accent2`: 보조(대비가 필요한 두 번째 계열)
- 다크 모드용 값도 함께 밝게 조정(템플릿에 자리 있음).

### 4. 슬라이드 타입 조합
템플릿의 타입을 골라 복제·수정한다:

| 타입 | 용도 | 클래스 |
|------|------|--------|
| **title** | 첫 장·구분 표지 | `h1.big` + `.sub` |
| **stat** | 수치로 결과·규모 | `.stats` 4칸 |
| **cols+points** | 설명 + 카드 | `.cols` + `ul.pts` + `.card` |
| **flow** | 파이프라인·단계 | `.flow` + `.node` + `.arrow` |
| **code+table** | 코드·표 대비 | `.cols` + `pre` + `table.t` |
| **checklist** | 따라하기·재현 | `.cols.tri` + `.tag` + `ul.pts` |
| **note** | 강조·교정·주의 | `.note`(.m/.v 색상) |
| **close** | 마지막 장 | `h1.big` + 링크 |

규칙:
- 첫 슬라이드에만 `class="slide active"`, 나머지는 `class="slide"`.
- `<title>`을 강의명으로, 하단 `.brand`를 과정명으로 채운다.
- `id="total"`은 JS가 자동 계산하므로 슬라이드 수를 세지 않아도 된다.

### 4-1. 발표자 노트 (내장 기능)
각 `<section class="slide">`에 **`data-note="발표 대사..."`** 속성을 달면, 발표자가 **N 키**(또는 🗒 버튼)로 여는 노트 패널에 자동 표시된다. 청중에겐 안 보이고 발표자만 본다.
- 노트는 요점 나열이 아니라 **실제 말할 대사** — 어떻게 말하고, 어디서 강조·멈출지까지 쓴다.
- 슬라이드를 넘기면 해당 장 노트로 자동 갱신된다(배선은 템플릿에 내장, 손댈 필요 없음).
- 노트가 없는 슬라이드는 빈 채로 둬도 된다.

### 5. 발행
Artifact 도구로 발행한다. 파일 경로는 `{프로젝트}/…/slides.html` 같은 안정적 경로로 두고, **장 추가·수정 시 같은 경로로 재발행**하면 같은 URL을 유지한다. favicon은 주제에 맞는 이모지 1개, 재발행 시 동일 유지.

## 슬라이드 작성 원칙 (Why)
- **한 화면 한 개념**: 슬라이드는 읽는 문서가 아니라 보는 것이다. 청중은 발표자를 보며 슬라이드를 훑는다. 문단을 넣으면 아무도 안 읽는다.
- **큰 타이포·짧은 문구**: 헤드라인은 크게, 요점은 명사구로. `text-wrap:balance`가 제목 줄바꿈을 정리한다.
- **시각 요소 하나**: 각 슬라이드에 표·코드·다이어그램·스탯 중 하나. 텍스트만 있는 슬라이드는 지루하다.
- **코드는 터미널 블록**: `pre`에 `.c`(주석)·`.g`(문자열)·`.w`(강조) 스팬으로 최소 하이라이트.
- **강조·교정은 note로**: "기억 교정", "흔한 실수", "완성 기준" 같은 핵심은 `.note` 박스로 눈에 띄게.

## 접근성·품질 체크
- 라이트/다크 양쪽에서 대비가 읽히는가(테마 토글로 확인).
- 방향키·버튼·스와이프·전체화면(F)이 동작하는가.
- 가로 스크롤이 생기지 않는가(넓은 표·코드는 자체 `overflow:auto`).
- `prefers-reduced-motion`에서 전환이 꺼지는가(템플릿 내장).

## 산출물
- `{경로}/slides.html` — 자체완결형 단일 파일(외부 폰트·스크립트 없음, CSP 안전)
- Artifact URL — 발행 후 사용자에게 조작법(←→·F·테마) 안내
