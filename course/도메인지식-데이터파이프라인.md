# 도메인 지식 — 데이터 파이프라인 정확 리뷰

> **하네스는 도구일 뿐입니다.** 수강생이 진짜 알아야 할 것은 아래 **데이터·좌표계·지도 API**의 실제 작동 방식입니다.
> 이 문서는 실제 프로젝트 파일을 검증해 작성했습니다. "아마도"가 아니라 **파일에서 확인한 사실**입니다.

---

## 0. 전체 그림 한 장

```
① 경매물건 (점 데이터)                  ② 정비구역 (면 데이터)
   법원경매 크롤링                          공공 GIS 포털 SHP 다운로드
   → 좌표 내장(TM128) 또는 VWorld 지오코딩    → 좌표계 변환(EPSG:5186→4326)
        │                                       │
        ▼                                       ▼
   WGS84 GeoJSON (Point)                   WGS84 GeoJSON (MultiPolygon)
        │                                       │
        └───────────────┬───────────────────────┘
                        ▼
             ③ 카카오맵 JavaScript API
                (개발자센터 JS 키)
                        ▼
                  estate_map.html
        경매=Marker+Clusterer / 정비구역=Polygon
```

세 데이터를 **모두 WGS84(위경도) GeoJSON으로 통일**한 뒤, **카카오맵 위에 레이어로 얹는 것**이 전부입니다. 나머지(에이전트·하네스)는 이 파이프라인을 자동화하는 수단입니다.

## 1. 경매물건 데이터 (점 레이어)

### 1-1. 출처와 수집
- **출처**: 법원경매정보(`courtauction.go.kr`)
- **수집 방식**: 검색 API(`searchControllerMain.on`)를 `pageNo`로 직접 페이징. UI 버튼 클릭은 물건을 대량 누락시키므로 API를 직접 호출.
- **원본 필드**(엑셀 컬럼, 실제 확인됨):
  | 컬럼 | 의미 |
  |------|------|
  | `saNo` | 사건번호 |
  | `yuchalCnt` | **유찰횟수** |
  | `gamevalAmt` | 감정가 |
  | `minmaePrice` | **최저매각가** |
  | `hjguSido` / `hjguSigu` | 소재지 시도/시군구 |
  | `maeGiil` | 매각기일 |
  | `maemulUtilCd`·`sclsUtilCd` | 물건 용도 |

### 1-2. 좌표 처리 — ★ 핵심 도메인 지식
경매 원본에는 **좌표가 이미 두 종류** 들어 있습니다:

| 컬럼 | 좌표계 | 사용 가능? |
|------|--------|-----------|
| `xCordi` / `yCordi` | **TM128 (KATEC, Bessel 타원체)** — 법원/네이버 레거시 | ✅ 정밀 |
| `wgs84Xcordi` / `wgs84Ycordi` | WGS84 | ❌ **정수로 반올림**돼 있어 못 씀 (127, 37) |

→ **`xCordi/yCordi`(TM128)를 `pyproj`로 WGS84(EPSG:4326)로 재투영**해서 씁니다. 이러면 지오코딩 API 호출 없이 정확한 좌표를 얻습니다.

```python
from pyproj import Transformer
# TM128(Bessel) → WGS84.  EPSG:5178 = Korea 2000 / Unified CS (TM128 계열)
tf = Transformer.from_crs("EPSG:5178", "EPSG:4326", always_xy=True)
lon, lat = tf.transform(xCordi, yCordi)
```

> ⚠️ 좌표가 없거나 변환 실패하는 물건(예: "자동차")은 **버리지 말고** `geocode_failed`로 집계하고, 지도 렌더 시 제외합니다. (그러지 않으면 null 좌표에서 지도 스크립트가 통째로 멈춥니다 — Part 3의 실제 버그.)

### 1-3. 백업 지오코딩 — VWorld (주소 → 좌표)
좌표가 아예 없는 경우를 위한 백업. `geocoding.py`는 **VWorld 주소 API**(`https://api.vworld.kr/req/address`)를 씁니다.
> 🔧 **기억 교정**: 지오코딩은 **카카오가 아니라 VWorld**입니다. 카카오 키는 *지도 표출*에만 쓰고, *주소→좌표 변환*은 VWorld 키를 씁니다. (두 키는 별개)

### 1-4. QGIS의 역할 — ★ 기억 교정
QGIS는 **데이터 생성 도구가 아니라 검증/시각화 도구**입니다.
- `qgis_export.py`가 지오코딩 결과를 **WGS84 GeoJSON으로 변환** → QGIS에서 열어 좌표가 엉뚱한 데 찍히지 않는지 눈으로 검증.
- 최종 웹 지도(카카오맵)에는 **QGIS가 관여하지 않습니다.** 파이프라인 중간 점검용입니다. (없어도 결과는 나옵니다.)

## 2. 정비구역 데이터 (면 레이어)

### 2-1. 왜 폴리곤인가 — ★ 핵심
경매물건은 **점**(위경도 하나)이지만, 정비구역은 **영역**입니다. "이 블록 전체가 재건축 구역" 같은 경계를 표현하려면 **Polygon / MultiPolygon** 지오메트리가 필요합니다. 그래서 점 데이터와는 **소스도 형식도 다릅니다.**

### 2-2. 실제 데이터 (파일에서 확인)
- 파일: `정비구역.geojson` — **서울 25개 자치구, 2,585건, MultiPolygon, WGS84**
- 필드(실제): `name`(구역명), `lclas_nm`(사업 대분류: 재건축/재개발/주거환경개선/가로주택 등), `sclas_nm`(정비단계), `propel_nm`(추진주체), `signgu`(법정동코드), `area_m2`, `created`(기준일 2025-12-31)
- 사업유형 분포: 재건축 1,014 · 재개발 740 · 주거환경개선 311 · 가로주택 293 · 소규모재개발 173 · 소규모재건축 54

### 2-3. 출처 — 정직하게
원본 파일에는 출처 메타가 없어(파일 안에 `crs`·`source` 기록 없음) **어느 포털에서 받았는지 100% 단정할 수 없습니다.** 다만 필드 스키마(`lclas`/`sclas`/`propel`/`signgu`)와 커버리지(서울 전역)로 볼 때 **한국 정부 도시정비 정비구역 표준 공간데이터**입니다. 재현 가능한 공식 출처는 아래 셋 중 하나:

| 포털 | 받는 형식 | 비고 |
|------|----------|------|
| **국가공간정보포털(NSDI)** `nsdi.go.kr` 오픈마켓 | SHP | '정비구역' 검색, 로그인·승인 필요 |
| **서울 열린데이터광장** `data.seoul.go.kr` | SHP/GeoJSON | 서울시 정비사업 정비구역 |
| **브이월드(VWorld)** `vworld.kr` 데이터 | WMS/일부 다운로드 | 도시계획 계열 |

> 사용자 기억("공공데이터포털 SHP 또는 브이월드")은 **방향이 맞습니다.** 정확히는 위 포털 계열에서 SHP로 받아 GeoJSON으로 변환한 것으로 보입니다.

### 2-4. SHP → WGS84 GeoJSON 변환 (재현 핵심)
포털에서 받은 SHP는 대개 **EPSG:5186(중부원점 TM)** 또는 **5179(UTM-K)** 좌표계입니다. 카카오맵에 올리려면 **WGS84(EPSG:4326)** 로 변환해야 합니다.

**방법 A — geopandas (코드):**
```python
import geopandas as gpd
gdf = gpd.read_file("정비구역.shp")      # SHP 읽기 (인코딩 cp949일 수 있음)
gdf = gdf.to_crs(epsg=4326)              # WGS84로 재투영
gdf.to_file("정비구역.geojson", driver="GeoJSON")
```

**방법 B — QGIS (GUI):**
1. QGIS에서 SHP를 레이어로 추가
2. 레이어 우클릭 → Export → Save Features As
3. Format: GeoJSON, CRS: **EPSG:4326 (WGS84)** 선택 → 저장

> ⚠️ **데이터 함정(실제 겪음)**: 이 데이터의 `signgu_nm`(자치구명) 속성이 코드와 **어긋나** 있었습니다(코드 11680=강남인데 이름은 "서초구"). → 이름을 믿지 말고 **법정동코드(`signgu`)를 표준 자치구표로 재매핑**하세요. **속성 맹신 금지.**

## 3. 카카오맵 (지도 표출)

### 3-1. JavaScript 키 발급 (재현 필수)
1. **카카오 개발자센터**(`developers.kakao.com`) 로그인
2. 내 애플리케이션 → 애플리케이션 추가
3. 앱 키 → **JavaScript 키** 복사 (무료)
4. **플랫폼 → Web → 사이트 도메인 등록**: `http://localhost:8000` 등
   > ⚠️ 도메인 미등록이면 지도가 안 뜹니다. `file://`로 직접 열면 거부될 수 있으니 로컬 서버 권장:
   > ```bash
   > python -m http.server 8000   # → http://localhost:8000/estate_map.html
   > ```

### 3-2. SDK 동적 로드 (실제 코드)
```javascript
var s = document.createElement('script');
s.src = 'https://dapi.kakao.com/v2/maps/sdk.js?appkey=' + KAKAO_KEY
      + '&autoload=false&libraries=clusterer';   // 클러스터러 라이브러리 포함
s.onload = function(){ kakao.maps.load(initMap); };
document.head.appendChild(s);
```
> 🔐 **키 보안**: JS 키를 HTML에 하드코딩하면 공개 저장소에서 유출됩니다. → 브라우저 `localStorage`에 저장하는 방식을 씁니다.

### 3-3. 레이어 올리기 — 점과 면

**경매물건 (점) — Marker + Clusterer:**
```javascript
var marker = new kakao.maps.Marker({ position: new kakao.maps.LatLng(lat, lon) });
clusterer.addMarker(marker);   // 9,759개는 반드시 클러스터링
```

**정비구역 (면) — Polygon:**
```javascript
// GeoJSON 좌표는 [경도, 위도] 순서, 카카오는 LatLng(위도, 경도) — 순서가 반대!
var path = ring.map(function(c){ return new kakao.maps.LatLng(c[1], c[0]); });
new kakao.maps.Polygon({ path: path, fillColor:'#7c3aed', fillOpacity:0.22 }).setMap(map);
```

> ⚠️ **가장 흔한 버그**: GeoJSON은 `[경도, 위도]`, 카카오 `LatLng`는 `(위도, 경도)`. **순서를 안 바꾸면** 폴리곤이 엉뚱한 곳(바다·다른 나라)에 그려집니다.

## 4. 좌표계 총정리 — ★ 반드시 이해할 도메인 지식

지도 프로젝트에서 버그의 절반은 좌표계에서 옵니다.

| 좌표계 | EPSG | 쓰임 | 순서/단위 |
|--------|------|------|-----------|
| **WGS84** | 4326 | 국제표준, 웹지도 표출 | 위경도(도) |
| TM128 / KATEC (Bessel) | 5178 | 법원경매·네이버 레거시 | 미터 |
| 중부원점 TM | 5186 | 공공 GIS SHP | 미터 |
| UTM-K | 5179 | 국가기본도 | 미터 |

**규칙**:
1. 최종 표출은 **무조건 WGS84(4326)** 로 통일한다.
2. 공공 SHP·법원 좌표는 대부분 미터 단위(5178/5186/5179) → **반드시 4326으로 재투영**.
3. GeoJSON 저장 순서는 `[경도, 위도]`, 카카오 API는 `(위도, 경도)` → **변환 지점마다 순서 확인.**

## 5. 수강생 재현 체크리스트 — "똑같은 결과 얻기"

아래를 순서대로 하면 동일한 `estate_map.html`이 나옵니다.

### 준비 (API 키 2개)
- [ ] **VWorld 인증키** (`vworld.kr`) — 주소 지오코딩·백업용
- [ ] **카카오 JavaScript 키** (`developers.kakao.com`) — 지도 표출용, Web 도메인 등록
- [ ] Python: `pip install pandas geopandas pyproj openpyxl requests`

### ① 경매물건 → WGS84 GeoJSON(점)
- [ ] 법원경매 API로 수도권 물건 수집 (또는 제공된 `auction_data_seoul_sudogun_*.xlsx` 사용)
- [ ] `xCordi/yCordi`(TM128) → pyproj로 EPSG:4326 재투영
- [ ] `saNo`·`yuchalCnt`·`minmaePrice`·`hjguSigu` 등 필드 보존, `sido/sigungu` 지역태그 부착
- [ ] 좌표 없는 물건 제외(실패율 기록) → `layer_auction.geojson`

### ② 정비구역 → WGS84 GeoJSON(면)
- [ ] NSDI/서울 열린데이터광장에서 서울 정비구역 SHP 다운로드
- [ ] geopandas 또는 QGIS로 **EPSG:4326 GeoJSON 변환**
- [ ] `signgu`(법정동코드)로 자치구명 재매핑 → `layer_zone_redev.geojson`

### ③ 카카오맵에 레이어 올리기
- [ ] 카카오 SDK 동적 로드(`libraries=clusterer`), 키는 localStorage
- [ ] 경매: `Marker` + `MarkerClusterer`
- [ ] 정비구역: `Polygon` — **LatLng(위도,경도) 순서 주의**
- [ ] 지역 드롭다운(sido→sigungu) 필터, 레이어 토글
- [ ] 로컬 서버(`python -m http.server`)로 열어 확인

### ✅ 완성 기준
- 카카오맵 위에 경매 마커(민트)와 정비구역 폴리곤(바이올렛)이 함께 보이고, 지역 선택으로 필터되며, 경매 마커 클릭 시 유찰횟수·주소·최저가가 뜬다.

## 부록 — 기억 교정 요약

| 사용자 기억 | 검증된 사실 |
|------------|------------|
| "경매 데이터에 경위도·기본정보가 있다" | ✅ 맞음. 단 표출용 좌표는 `wgs84` 컬럼(정수반올림)이 아니라 **`xCordi/yCordi`(TM128) 재투영** |
| "QGIS가 활용됐는지 모르겠다" | 🔧 **검증/시각화용**으로 쓰임(`qgis_export.py`). 최종 웹지도엔 미관여 |
| "정비구역은 공공데이터포털 SHP일 것" | ✅ 방향 맞음. NSDI/서울 열린데이터광장 계열 SHP → GeoJSON 변환(폴리곤이라 SHP 필요) |
| "브이월드에서 받았을 수도" | 가능. VWorld는 **지오코딩(주소 API)** 에 확실히 쓰였고, 정비구역 경계 출처는 단정 불가 |
| "카카오 개발자센터 JS API로 지도" | ✅ 정확. `dapi.kakao.com` SDK 동적 로드 + 정비구역 Polygon 오버레이 |
