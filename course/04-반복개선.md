# Part 4. 반복 개선 — 하네스 진화

> 하네스는 한 번 만들고 끝이 아닙니다. **여러분이 피드백을 주면** 에이전트가 고칩니다. 이 파트는 우리가 실제로 주고받은 요청과 결과를 그대로 재현합니다. 여기서 배우는 건 **"무엇을 어떻게 요청하는가"** 입니다.

## 🎯 학습목표
- 부분 개선을 짧은 요청으로 지시한다
- 데이터 확장과 UI 기능 추가를 올바른 순서로 요청한다
- 데이터가 없을 때 정직한 처리를 받아들인다

---

## 4.1 카카오맵 전환 + 마커 대비 개선

### ⌨️ 여러분이 입력하는 것
```
카카오맵을 이용해서 보여줘. 그리고 마커 색상이 지도 배경과 구분이 잘 안돼
```

### 에이전트가 하는 일
전체를 다시 돌리지 않고 **map-integrator(렌더 담당)만** 재작업합니다:
- 베이스맵 → 카카오맵 (일반/스카이뷰/하이브리드)
- 마커를 핀형 + 흰 외곽선으로 → 밝은 배경에서도 또렷하게

### 여러분이 알아야 할 것
- 카카오맵은 **본인 JS 앱키**가 필요합니다 (무료 발급). 지도를 열면 키 입력창이 뜨고, 한 번 넣으면 저장됩니다.

> 💡 **배울 점**: "지도만 바꿔줘"처럼 **부분 요청**을 하면 에이전트가 해당 담당만 재실행합니다. 전체 재수집을 안 하니 빠릅니다.

<details>
<summary>🔍 심화 — 카카오 키를 코드에 넣으면 안 되는 이유</summary>

키를 HTML에 하드코딩하고 공개 저장소에 올리면 **유출**됩니다. 그래서 브라우저 localStorage에 저장하는 방식을 씁니다. `file://`로 열면 카카오 SDK가 도메인을 거부할 수 있는데, 그땐 `python -m http.server`로 `localhost` 접속하면 됩니다.
</details>

## 4.2 서울+수도권 확장 + 지역 선택 기능

### ⌨️ 여러분이 입력하는 것
```
분당구만 했는데 서울 포함 수도권이 나오도록 하고, 지역을 선택할 수 있게 해줘
```

### 에이전트가 하는 일 (두 단계, 순서 중요)
1. **경매 수집가**가 분당 필터를 풀고 서울+수도권 전체로 확장 + 각 물건에 지역 태그(시도·시군구)를 붙임 → **9,759건**
2. **렌더 담당**이 그 태그로 지역 드롭다운(시도→시군구)을 만들고, 선택 시 필터 + 지도 이동

### 여러분이 알아야 할 핵심
> 💡 지역 선택 같은 **UI 기능은 데이터에 태그가 있어야** 가능합니다. 그래서 "UI 먼저"가 아니라 **"데이터(수집) 먼저, 화면(렌더) 나중"** 순서로 진행됩니다. 이 순서 감각이 실무에서 중요합니다.

## 4.3 정비구역 데이터 확보의 현실 — 없을 때 정직하게 ⭐

> 이 사례가 실무에서 가장 중요합니다. **데이터가 없을 때 에이전트가 어떻게 반응해야 하는가?**

### 무슨 일이 있었나
처음 분당구 정비구역을 찾았지만 공개 데이터에 없었습니다. 에이전트는 **억지로 지어내지 않고** `0건`으로 두되, **왜 없는지**를 조사해 남겼습니다:
- 분당구엔 실제 정비구역이 있음 (2026.4 노후계획도시 선도지구 지정)
- 단지 최신이라 공개 공간데이터에 아직 미반영
- 시도한 4개 소스와 각각의 실패 사유 기록

지도에도 "데이터 없음"이 아니라 **"경계 미확보 ⓘ"** + 툴팁으로 근거를 표시했습니다.

### 반전
서울로 확장하자, "서울 전용이라 못 쓰던" 데이터가 **유효한 소스**가 됐습니다 → 서울 25개 자치구 **2,585건**(재건축1,014·재개발740 등) 확보.

> 💡 **세 가지 교훈**:
> 1. 데이터가 없으면 **억지로 만들지 말고** 사유를 기록하라 (환각 방지)
> 2. **"없음"과 "미확보"는 다르다** — 사용자에게 정직하게 구분해 전달하라
> 3. 스코프가 바뀌면 못 쓰던 데이터가 유효해질 수 있다

<details>
<summary>🔍 심화 — 데이터 품질 함정 (속성 맹신 금지)</summary>

정비구역 원본의 자치구명 속성이 코드와 **어긋나** 있었습니다 (코드 11680=강남인데 이름은 "서초구"). 에이전트는 이름을 믿지 않고 **법정동코드를 표준표로 재매핑**했습니다. → 데이터 속성을 맹신하지 말고 교차검증하라는 실전 교훈.
</details>

## 4.4 색상 반복 튜닝

### ⌨️ 여러분이 입력하는 것
```
경매 마커색과 정비구역색이 비슷하다. 경매를 민트로 바꾸고,
정비구역도 지도색과 대비되는 색으로 바꿔줘
```

### 에이전트가 하는 일
- 경매 마커: **민트 #20c997**
- 정비구역: **바이올렛 #7c3aed** (민트의 보색 → 확실히 구분)
- 범례·팝업 강조색까지 자동 동기화

### 곁들인 교훈: 추측 대신 데이터로 확인
"송파구 경매가 없다"고 느껴지면, 에이전트는 **데이터로 확인**합니다 → 실제로 그 스냅샷엔 송파구가 0건(필터 버그 아님)이었습니다. 추측하지 말고 데이터로 답하는 태도.

> 💡 **배울 점**: 색 하나 바꾸는 작은 요청일수록 범위를 좁게 주면("색상만") 안전합니다.

## 4.5 결과를 저장하기 — 안전 확인은 에이전트가

### ⌨️ 여러분이 입력하는 것
```
github의 내 저장소로 커밋하고 푸시해줘
```

### 에이전트가 자동으로 챙기는 것
- **어느 저장소인지** 확인 (엉뚱한 곳에 올리지 않게)
- **민감정보 스캔** (API 키·비밀번호가 섞이지 않았는지)
- 안전하면 커밋·푸시, 변경 이력 기록

### 여러분이 알아야 할 것
> 💡 실제로 우리 프로젝트에선 홈 폴더 전체가 저장소여서 `.ssh`·`.env` 같은 **민감정보가 유출될 뻔했습니다.** 에이전트가 이를 발견하고 **프로젝트 폴더만 분리**해 올렸습니다. — 여러분이 직접 git을 몰라도, "안전하게 올려줘"라고 하면 에이전트가 이런 위험을 점검합니다.

<details>
<summary>🔍 심화 — push 전 안전 점검 흐름</summary>

에이전트는 push 전에 저장소 루트(`git rev-parse --show-toplevel`)와 원격 주소를 확인하고, 키·토큰 패턴을 스캔합니다. 홈 디렉토리가 통째로 저장소이거나 민감정보가 있으면 프로젝트 폴더만 독립 저장소로 분리합니다. 세부 명령을 몰라도 되지만, **push 전 확인**이라는 원칙은 기억하세요.
</details>
