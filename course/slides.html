좌표는 이미 데이터 안에 있다

법원경매 원본에 좌표가 두 종류 들어 있다. 어느 걸 쓰느냐가 관건.

컬럼좌표계사용
xCordi/yCordiTM128(KATEC)✔ 정밀
wgs84XcordiWGS84✘ 정수반올림
# TM128(Bessel) → WGS84 재투영
from pyproj import Transformer
tf = Transformer.from_crs(
     "EPSG:5178", "EPSG:4326",
     always_xy=True)
lon, lat = tf.transform(xCordi, yCordi)
기억 교정표출 좌표는 wgs84 컬럼(반올림돼 못 씀)이 아니라 xCordi/yCordi(TM128)를 재투영한 값이다.
① 경매 · 보조 지오코딩

  • 좌표가 없는 물건은 주소 → 좌표 변환이 필요

기억 교정

QGIS는 검증 도구다

qgis_export.py가 지오코딩 결과를 WGS84 GeoJSON으로 변환 → QGIS에서 좌표가 엉뚱한 데 찍히지 않는지 눈으로 확인.

  • 데이터 생성 도구가 아님
  • 최종 웹지도(카카오맵)엔 미관여
  • 없어도 결과는 나온다 — 중간 점검용

② 정비구역 · 면 레이어

왜 폴리곤인가

경매물건은 점(위경도 하나). 정비구역은 영역 — "이 블록 전체가 재건축 구역".

  • 경계를 표현하려면 Polygon / MultiPolygon
  • 그래서 소스도 형식도 다르다
  • 서울 25개 자치구 2,585건
    (재건축1,014·재개발740…)
공간데이터

출처 (재현 경로)

NSDI 국가공간정보포털 · 서울 열린데이터광장 · VWorld 계열에서 SHP 다운로드

폴리곤이라 SHP가 필요하다

② 정비구역 · 변환

SHP → WGS84 GeoJSON

공공 SHP는 대개 EPSG:5186 / 5179(미터). 카카오맵에 올리려면 4326(위경도)으로 변환해야 한다.

방법 A · geopandas
import geopandas as gpd
g = gpd.read_file("정비구역.shp")
g = g.to_crs(epsg=4326)   # WGS84
g.to_file("정비구역.geojson",
          driver="GeoJSON")
방법 B · QGIS
  • SHP를 레이어로 추가
  • Export → Save Features As
  • GeoJSON + CRS: EPSG:4326
데이터 함정signgu_nm(자치구명)이 코드와 어긋남(11680=강남인데 "서초구") → 법정동코드로 재매핑. 속성 맹신 금지.

③ 카카오맵 · 최다 버그

좌표 순서가 반대다

GeoJSON은 [경도, 위도], 카카오 LatLng는 (위도, 경도). 안 바꾸면 폴리곤이 바다에 그려진다.

레이어카카오 객체
경매 · 점Marker + MarkerClusterer
정비 · 면Polygon
// GeoJSON [lng,lat] → LatLng(lat,lng)
var path = ring.map(c =>
   new kakao.maps.LatLng(
       c[1],  // 위도 (lat)
       c[0]   // 경도 (lng)
   ));
new kakao.maps.Polygon({path}).setMap(map);

품질 검증 · 실전

지도가 텅 비었다

마커·폴리곤이 하나도 안 보였다. 원인은 좌표 없는 물건 2건.

  • 경매 64건 중 2건이 geometry:null("자동차")
  • 렌더 루프가 방어 못해 스크립트 전체 중단
  • → 아무것도 안 보임
features.forEach(f => {
  if(!f.geometry) return; // 방어 가드
  var c = f.geometry.coordinates;
  // ... 마커 생성
});
교훈계약에 "좌표 필수"가 있어도 렌더러는 방어적으로. 독립 QA가 이걸 잡는다.
