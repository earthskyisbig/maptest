## 0.1 우리가 만들 것

**최종 산출물**: 하나의 HTML 파일(`estate_map.html`) — 카카오맵 위에 두 개의 레이어가 얹힌 인터랙티브 부동산 지도.

- 🟢 **경매물건 9,759건** (서울+수도권) — 민트색 핀, 클릭하면 유찰횟수·주소·최저가 팝업
- 🟣 **정비구역 2,585건** (서울 25개 자치구) — 바이올렛 폴리곤
- 📍 **지역 선택 드롭다운** — 시도→시군구로 필터링
- 🔀 레이어 on/off 토글, 마커 클러스터링

이걸 손으로 다 코딩하면 며칠이 걸립니다. 우리는 **에이전트 팀에게 역할을 나눠 시켜** 이걸 만듭니다.

### 이 강의의 진짜 목표

지도는 "예제"일 뿐입니다. 진짜 배우는 것은:

> **도메인을 전문 에이전트로 분해하고, 각자에게 스킬을 쥐어주고, 팀으로 협업시켜 결과를 만드는 설계 능력**

이 능력은 "쇼핑몰 상품 크롤링 + 분석 + 리포트", "논문 수집 + 요약 + 인용검증" 등 어떤 도메인에도 그대로 옮겨집니다.

## 0.2 왜 "에이전트 한 대"가 아니라 "팀"인가

초보자는 보통 이렇게 시작합니다:

> "Claude야, 경매물건이랑 정비구역이랑 인프라 다 모아서 지도 만들어줘"

이 방식의 문제:
- **컨텍스트 폭발**: 한 대화에 크롤링·지오코딩·GIS·렌더링·QA가 다 섞여 길을 잃는다
- **병렬 불가**: 경매 수집이 끝나야 인프라 수집을 시작 → 느리다
- **재사용 불가**: 다음에 "인천만 다시" 하려면 처음부터 다시 설명해야 한다
- **품질 검증 부재**: 누가 결과를 검사하는가?

**에이전트 팀 방식**:
- 경매 전문가, 구역 전문가, 인프라 전문가가 **동시에 병렬로** 수집
- 통합 담당이 표준 규격으로 병합
- QA 담당이 독립적으로 검증
- 각 전문가는 파일로 정의돼 **다음에도 재사용**

이 구조를 우리는 **하네스(Harness)** 라고 부릅니다. Part 1에서 자세히 다룹니다.

## 0.3 폴더 구조와 준비

### ⌨️ 따라하기: 작업 폴더 만들기

```bash
mkdir maptest
cd maptest
```

이 안에 최종적으로 아래 구조가 만들어집니다:

```
maptest/
├── CLAUDE.md                    # 하네스 포인터 (새 세션이 읽는 안내문)
├── .claude/
│   ├── agents/                  # 에이전트 정의 5종 (누가 일하는가)
│   │   ├── auction-collector.md
│   │   ├── zone-layer-specialist.md
│   │   ├── poi-collector.md
│   │   ├── map-integrator.md
│   │   └── qa-validator.md
│   └── skills/                  # 스킬 (어떻게 하는가)
│       ├── layer-auction-collect/
│       ├── layer-zone-boundary/
│       ├── layer-infra-poi/
│       ├── map-render/
│       └── realestate-map-build/    # 오케스트레이터
│           └── references/geojson-schema.md   # 표준 데이터 계약
├── _workspace/                  # 에이전트들의 중간 산출물 (레이어 GeoJSON)
└── estate_map.html              # 최종 지도
```

### ✅ 체크포인트
- `maptest` 폴더가 만들어졌는가
- Claude Code를 이 폴더에서 실행할 수 있는가 (`claude` 명령)
