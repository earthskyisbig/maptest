# Part 2. 하네스 구축 실습

> 에이전트 5종 + 스킬 5종 + 데이터 계약을 만듭니다. **여러분이 파일을 손으로 짜는 게 아닙니다.** `/harness`를 트리거하고 도메인을 설명하면 Claude가 생성합니다. 여러분의 일은 **설계 의도를 전달하고, 생성된 것을 검토하는 것**입니다.

## 🎯 학습목표
- 도메인을 전문 에이전트로 분해하는 사고를 익힌다
- `/harness`로 하네스를 생성시키고 결과를 검토한다
- 무엇을 확인해야 "잘 만들어졌다"고 할 수 있는지 안다

---

## 2.1 도메인 분석 & 에이전트 분리 — 수강생의 핵심 판단

여기가 여러분이 실제로 **머리를 쓰는** 지점입니다. 레이어가 5개라고 에이전트를 5명 만들면 과합니다. **데이터 소스의 성격**으로 묶습니다:

| 레이어 | 소스 성격 | 담당 |
|--------|----------|------|
| 경매물건 | 법원경매 크롤 + 지오코딩 | `auction-collector` |
| 정비구역·공공주택·산업단지 | **GIS 경계(WMS/공공데이터)** — 기법 동일 | `zone-layer-specialist` (1명) |
| 생활인프라 | Overpass/POI | `poi-collector` |
| (통합) | 표준 GeoJSON 병합 → 지도 | `map-integrator` |
| (검증) | 좌표·스키마·정합 | `qa-validator` |

> 💡 **핵심 통찰**: 정비·공공주택·산단은 셋 다 "면 경계를 공공 GIS에서 가져온다"는 점이 같습니다. 소스 기법이 같으면 한 에이전트로 묶어 조율 오버헤드를 줄입니다. 이것이 "5레이어 → 4수집단위" 판단입니다.

이 판단(어떻게 나눌지)만 여러분이 정하면, 파일 생성은 Claude가 합니다.

## 2.2 ⌨️ 따라하기: /harness 트리거

Claude Code에서 이렇게 입력합니다:

```
/harness 부동산 전용 맵서비스를 만들 거야. 경매물건, 정비구역, 공공주택,
산업단지, 생활인프라를 한 지도 위에 레이어로 보여주고 싶어.
```

### 에이전트가 하는 일 (여러분은 지켜봅니다)
1. 기존 하네스 유무를 **감사** (신규/확장 판별)
2. 도메인을 분석해 **에이전트 분리안**을 제시
3. 확인을 받은 뒤 `.claude/agents/` 5종, `.claude/skills/` 5종, 데이터 계약, `CLAUDE.md`를 **자동 생성**

### 여러분이 보게 되는 결과
```
maptest/
├── CLAUDE.md
├── .claude/agents/     (5개: auction-collector, zone-layer-specialist,
│                             poi-collector, map-integrator, qa-validator)
└── .claude/skills/     (5개: layer-*, map-render, realestate-map-build)
        └── references/geojson-schema.md   ← 표준 데이터 계약
```

### 여러분이 내리는 판단
Claude가 분리안을 제시하면, 여러분은:
- **동의**하거나 → "그대로 진행"
- **조정**을 요청 → "정비구역은 따로 빼줘" 같은 피드백

## 2.3 생성된 것 검토하기 — 무엇을 확인하나

파일을 직접 쓰지 않았어도, **잘 만들어졌는지 읽어볼 수 있어야** 합니다.

### 에이전트 정의에서 확인할 것
각 `.claude/agents/*.md`가 이런 골격을 갖췄는지:
- **핵심 역할** — 한 문장으로 명확한가
- **작업 원칙** — "왜"가 설명돼 있는가 (예: "좌표가 데이터의 생명")
- **입출력 프로토콜** — 무엇을 받아 무엇을 내는가
- **팀 통신** — 누구에게 보고하는가

<details>
<summary>🔍 심화 — 실제 에이전트 정의 파일 (auction-collector.md)</summary>

```markdown
---
name: auction-collector
description: 경매물건 레이어 데이터 수집가. 법원경매 물건을 수집하고
  지오코딩하여 표준 GeoJSON Point 레이어로 산출한다.
model: opus
---
# auction-collector — 경매물건 레이어 수집가

## 핵심 역할
법원경매 물건을 수집하고, 주소를 좌표로 지오코딩하여
표준 GeoJSON Point 레이어를 만든다.

## 작업 원칙
- 목록수집은 API 직접 페이징 (UI 클릭은 대량 누락)
- 좌표가 데이터의 생명 — 지오코딩 실패 물건은 버리지 말고
  geocode_failed=true로 남기고 실패율을 리포트

## 팀 통신 프로토콜
- 발신: map-integrator에게 파일 경로, qa-validator에게 실패율
```

이 전문은 저장소 `.claude/agents/`에서 볼 수 있습니다. 규칙: 모든 에이전트는 파일로 정의되고 `model: opus`를 씁니다.
</details>

### 스킬에서 확인할 것
- `description`에 **실제 사용자 표현**("만들어줘", "수집", "갱신")이 들어있는가 (트리거 확보)
- 본문이 500줄 이내인가

<details>
<summary>🔍 심화 — 실제 스킬 파일 (layer-auction-collect)</summary>

```markdown
---
name: layer-auction-collect
description: 경매물건 레이어 수집. …"경매 레이어 만들어줘", "경매물건 수집",
  "경매 지도 갱신" 요청 시 사용.
---
## 워크플로우
1. 목록 수집 — API 직접 페이징 (UI 클릭 금지)
2. 지오코딩 — 실패 주소는 geocode_failed로 보존
3. GeoJSON 변환 — references/geojson-schema.md 규격

## 왜 이렇게 하는가
- API 페이징: UI는 누락되지만 API는 결정적이다
- 실패 주소 보존: 실패율은 데이터 품질 지표다
```
</details>

## 2.4 오케스트레이터와 CLAUDE.md — 자동 등록 확인

`/harness`는 팀 전체를 엮는 **오케스트레이터 스킬**(`realestate-map-build`)과, 새 세션이 읽는 **CLAUDE.md 포인터**까지 만들어 등록합니다.

여러분이 확인할 것:
- 오케스트레이터 description에 **후속 키워드**("다시/재실행/추가/수정")가 있는가 → 없으면 "지도 다시 만들어줘" 같은 후속 요청이 트리거 안 됨
- CLAUDE.md에 **트리거 규칙 + 변경 이력**만 있는가 (에이전트 목록·디렉토리 구조를 넣으면 중복)
